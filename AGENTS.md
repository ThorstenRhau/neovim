# Neovim Configuration

Personal Lua configuration for Neovim 0.12+.

## Layout

- `init.lua` sets leaders and loads core modules from `lua/config/`.
- `lua/config/pack.lua` declares plugins; `lua/plugins/` contains plugin setup
  and plugin keymaps.
- Put heavier filetype-specific behavior in `after/ftplugin/`.
- External LSP servers, formatters, and linters are Homebrew-managed as
  documented in `README.md`. Do not add Mason or another in-Neovim tool
  installer unless requested.

## Plugin model

- Use native `vim.pack.add()` only. Keep plugin declarations and `PackChanged`
  hooks in `lua/config/pack.lua`.
- Configure user-authored plugins eagerly during startup. Do not add first-use
  wrappers, proxy functions, or command hooks for setup.
- Treat `nvim-pack-lock.json` as generated by `vim.pack.update()`. Review
  intentional revision changes and commit them with related plugin
  configuration. Cleanup must preserve the lockfile.

## Conventions

- Let `.stylua.toml` and `selene.toml` define Lua style and lint policy.
- Every keymap must include `desc`; preserve established leader groups and use
  buffer-local mappings for filetype- or LSP-specific behavior.

## Validation

- Run `make check` after Lua changes. Use `make lint` for a narrower lint-only
  pass. There is no test suite.
- Do not use `make all` for verification because it rewrites Lua, and do not use
  `make clean` unless explicitly requested because it deletes live Neovim
  cache, state, and data.
- Verify unstable Neovim and plugin APIs with current `:help`, official upstream
  documentation, or Context7.
