# Neovim Configuration

Small personal Lua configuration for Neovim 0.12.x and compatible stable
releases.

## Layout and conventions

- Keep the configuration simple.
- Prefer direct Neovim settings and plugin setup. Add fault handling only for
  problems demonstrated in normal workflows, not for hypothetical scenarios.
- `init.lua` enables `vim.loader`, sets leaders, and loads `lua/options.lua`,
  `plugins.lua`, `keymaps.lua`, `lsp.lua`, and `autocmds.lua`.
  Keep these modules direct and self-contained.
- Declare packages and the Tree-sitter update hook in `lua/plugins.lua` using
  native `vim.pack.add()`. Configure plugins eagerly during startup.
- External language servers, formatters, and linters are Homebrew-managed; see
  `README.md`. Parser installation is explicit.
- Keep `nvim-pack-lock.json` local, untracked, and generated by native
  `vim.pack` operations. Preserve installed packages, parsers, and user data
  except when the user explicitly invokes `make clean` for a full reset.
- Use native filetype indentation with a two-space fallback and EditorConfig
  precedence.
- Every custom keymap needs `desc`. Keep LSP and Git inspection mappings
  buffer-local and preserve native mappings outside the documented overrides.
- Let `.stylua.toml` and `selene.toml` define style and lint policy.
- `.emmyrc.json` holds the Neovim-specific emmylua_ls settings, so other Lua
  projects get emmylua_ls defaults. It disables the type checks that mostly
  report false positives here: plugins annotate their types for LuaLS, and
  emmylua_ls treats indexing a `table<K, V>` as never nil.
- `workspace.library` in `.emmyrc.json` lists the `lua/` directory of each
  `vim.pack` plugin, because emmylua_ls resolves `require()` only directly
  under a library root and does not expand globs. Add or remove the entry
  when a plugin with a `lua/` directory is added to or removed from
  `lua/plugins.lua`.

## Validation and review

- Run `make check` after Lua changes and `git diff --check` before handoff.
  `make lint` checks Selene only; `make format` explicitly rewrites Lua.
- Run `make startup` against installed dependencies after changes affecting
  configuration behavior. It is neither isolated nor guaranteed offline. Verify
  affected interactive workflows separately; report anything unverified.
- Verify Neovim and plugin APIs against installed help/source, falling back to
  official online documentation when local information is missing or
  insufficient. Match documentation to the local revisions. Check package load
  order, mapping scope, and native indentation when relevant.
- Neovim's help and Lua source live in `/opt/homebrew/share/nvim/runtime`
  (`doc/`, `lua/vim/`); installed plugins live in
  `~/.local/share/nvim/site/pack/core/opt/`. `$VIMRUNTIME` is unset in agent
  shells; if needed, resolve it with
  `nvim --headless --clean '+lua io.write(vim.env.VIMRUNTIME)' +qa`.
- Reviews are read-only and findings-first. Report reproducible problems and
  distinguish configuration defects from missing tools or installation drift.
- Keep changes small. Do not modify `README.md` unless the user explicitly
  permits it. Do not introduce automatic tool installation or runtime cleanup.
- `make clean` is explicitly destructive. Test it only with disposable
  configuration and XDG directories, never against the live installation.
